# 2026-11-07 — 3.0.0 (comandos `/jarvis-*`, alinhados ao Spec Kit)

Mudança incompatível: os comandos mudam de nome e o fluxo ganha o passo `tasks`.

## O que mudou

- feat!: prefixo dos comandos `specnico-*` → `jarvis-*` (ex.: `/jarvis-constitution`). O pacote npm continua `specnico`
- feat!: `/specnico-spec` → `/jarvis-specify`
- feat!: novo `/jarvis-tasks`: toda a decomposição em ondas (`tasks.md`) saiu do `/jarvis-plan`, que agora só gera `plan.md`. Nova fase `tasks` no `state.json` (mapeia para `Status: review`)
- feat!: `/specnico-approve` removido. O gate humano passou para o início do `/jarvis-implement` (valida o pacote, pede a confirmação e passa `review → approved`); a skill agora é `disable-model-invocation`. O status `approved` deixou de existir no backlog (`spec → in-progress`)
- feat: `--upgrade`/`--force` removem as skills `specnico-*` antigas (só o `SKILL.md` entregue; arquivos do usuário ficam); `--check` avisa quando ainda existem
- docs: README com coluna Obrigatório/Opcional por comando, recomendação do Caveman e das skills globais do Nico Skills

## Atualizar

`npx specnico@latest --upgrade`. Depois, em `.claude/settings.json`, troque
`jarvis-approve` por `jarvis-implement` nas entradas de `permissions.deny` do
`settings.example.json`, se você as copiou. Specs em andamento com fase
`plan` e sem `tasks.md`: rode `/jarvis-tasks`.
