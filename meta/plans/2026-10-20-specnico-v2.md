# Specnico 2.0 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Transformar o `@robertourias/scaffold-ia` 1.x no pacote `specnico` 2.0.0: layout `.specify/` + `specs/`, 10 comandos `/specnico-*` como skills, Spec em pasta (spec/plan/tasks), `state.json`, product backlog gerado pela constituição, CLI com `--migrate` e README novo.

**Architecture:** Primeiro a mudança mecânica de layout (git mv + troca de caminhos), mantendo os testes verdes. Depois o hook `spec-gate` passa a ler `state.json` e `specs/*/`, os templates novos ganham teste de estrutura, e os comandos são reescritos como skills `specnico-*` a partir dos comandos 1.x que absorvem. CLI e documentação por último, quando os caminhos finais existem.

**Tech Stack:** Markdown (skills, agentes, templates, em português), Node ≥ 18 ESM/CJS sem dependências (hooks, CLI, testes `node:test`), Mermaid CLI via `npx` (diagrama).

**Spec:** `meta/specs/2026-10-20-specnico-v2-design.md`

**Decisões do plano (não explícitas na spec):**
- Em `.specify/memory/`, `constitution.md`, `product.md` e `product-backlog.md` são publicados como **stubs** (marcador vazio + ponteiro para o template); a estrutura vive só em `.specify/templates/*-template.md`. `architecture.md`, `conventions.md`, `decisions.md` e `domains/` mantêm a estrutura atual, com o marcador `**Status do arquivo:** vazio`.
- O `spec-gate` lê o `state.json` dentro do próprio hook (sem módulo compartilhado): nenhum outro código JS precisa dele.
- `--upgrade` sobre uma instalação 1.x (tem `.claude/.scaffold-version`, não tem `.specify/`) recusa e manda usar `--migrate`.
- Trabalho em um branch `feat/specnico-v2`; um commit por task.

## Global Constraints

- Textos do harness em português, no estilo dos arquivos existentes. Zero dependências novas.
- Testes: `node --test "meta/tests/*.test.mjs"`; lint: `node meta/tests/lint-docs.mjs`; pacote: `node meta/tests/check-maintenance.mjs`; EOL: `node meta/tests/check-eol.mjs`. **Os quatro verdes ao fim de cada task.**
- Pacote: `name: "specnico"`, `version: "2.0.0"`, `bin: { "specnico": "bin/cli.js" }`.
- Versão instalada: `.specify/.specnico-version`; legado reconhecido: `.claude/.scaffold-version`.
- Desligar hooks: `SPECNICO_VERIFY=0`; `SCAFFOLD_VERIFY=0` aceito como alias.
- Skills de comando, exatamente: `specnico-constitution`, `specnico-spec`, `specnico-clarify`, `specnico-plan`, `specnico-analyze`, `specnico-approve`, `specnico-implement`, `specnico-converge`, `specnico-review`, `specnico-fix`. Skills de papel sem prefixo: `backend`, `frontend`, `planner`, `quality`, `verification`.
- `specnico-approve` com `disable-model-invocation: true`.
- Spec: pasta `specs/NNN-slug/` (NNN = 3 dígitos sequenciais, ignorando `bugs/` e `legacy/`), branch `spec/NNN-slug`. Status da Spec: `review | approved | done` (só em `spec.md`).
- Backlog: IDs `Bnn` estáveis; Status `backlog → spec → approved → in-progress → done | descartado`; Tipo `fundação | arquitetura | feature`; features `F-<SIGLA>`, Status `planejada | live`.
- `state.json`: `{ "versao": 1, "ativo": { "spec", "item", "fase", "branch" } | null, "atualizado" }`; `fase ∈ spec | clarify | plan | approved | implement | converge`.
- Commits do fluxo: `docs(spec): <título> (review)`, `docs(spec): aprova NNN-slug`, `<tipo>(<escopo>): NNN-slug — onda N (T001, T002)`, `docs(spec): conclui NNN-slug`, `fix(<escopo>): <slug>`.
- Reasons exatos do hook: `Aprovação de Spec exige confirmação humana (/specnico-approve).` e `Emenda em Spec aprovada — registre o que mudou e por quê em ## Emendas.`
- Nenhum comando instrui `git add -A`, `git add .` ou `git commit -a`. Stage só caminhos explícitos.
- Commits terminam com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` (ou o modelo que de fato escreveu).

## Review Focus

- `npx specnico --migrate` rodado duas vezes: a segunda execução diz "nada a migrar" e não altera nada. Teste na Task 11.
- `npx specnico --upgrade` num projeto 1.x: deve recusar e apontar `--migrate`, não instalar um `.specify/` vazio ao lado do `docs/` preenchido. Teste na Task 10.

- README citando um comando removido fora da seção de migração (ex: `/hands-on` no exemplo de uso) → `lint-docs` falha. Teste na Task 12.
