# Checklist de qualidade da Spec: <título>

**Spec:** ../spec.md | **Validado em:** YYYY-MM-DD

> Qualidade do requisito, não da implementação. Itens falhos voltam à Spec;
> validar até 3 iterações.

## Qualidade do conteúdo
- [ ] Sem detalhe de implementação (linguagem, framework, API, caminho de arquivo)
- [ ] Foco no valor para o usuário e na necessidade do negócio
- [ ] Escrita compreensível por quem não é técnico
- [ ] Todas as seções obrigatórias preenchidas

## Completude dos requisitos
- [ ] Nenhum `[NEEDS CLARIFICATION]` restante (máximo 3 ao gerar)
- [ ] Requisitos testáveis e sem ambiguidade
- [ ] Critérios de sucesso mensuráveis
- [ ] Critérios de sucesso agnósticos de tecnologia
- [ ] Cenários de aceite definidos para cada story
- [ ] Casos de borda identificados
- [ ] Escopo claramente delimitado (Fora do escopo)
- [ ] Dependências e premissas identificadas

## Prontidão da feature
- [ ] Todo FR tem critério de aceite claro
- [ ] Stories cobrem os fluxos principais
- [ ] A feature atende os resultados mensuráveis dos Critérios de sucesso
- [ ] Nenhum detalhe de implementação vazou para a Spec
